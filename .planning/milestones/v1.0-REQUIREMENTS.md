# Plano Certo - Requirements Specification (Archived v1.0)

Este documento lista os requisitos que foram implementados e homologados no marco v1.0.

## Requisitos Funcionais

### RF-01: Inbox Unificado (WhatsApp + Instagram) [x]
- O corretor deve visualizar em uma única tela todas as conversas ativas.
- Cada conversa deve possuir um indicador visual de qual canal ela provém.
- As mensagens devem ser trocadas em tempo real utilizando Supabase Realtime para a tabela `messages`.

### RF-02: Automação Inbound (Agente Autônomo RAG) [x]
- Mensagens recebidas que tocarem em dúvidas regulatórias (ANS) ou detalhes de catálogo comercial devem ser respondidas de forma autônoma pela IA.
- O agente deve citar fontes de documentos ANS cadastrados na base para perguntas sobre cobertura, carência, reajuste ou portabilidade.
- Toda resposta automática gerada pelo agente deve ser inserida em `messages` com `sender_type = 'agent'`.

### RF-03: Campanha Outbound e Fila de Aprovação [x]
- Campanhas ativas (WhatsApp/Instagram) iniciam através de templates pré-aprovados ou propostas de mensagens personalizadas pela IA.
- O corretor deve visualizar propostas de mensagens outbound em uma fila de aprovação (`human_approvals`).
- O corretor pode aprovar, editar ou rejeitar a mensagem sugerida.
- O envio físico das mensagens aprovadas será realizado pela API do WhatsApp Business ou Instagram API através do n8n.

### RF-04: Prospecção Google Places Otimizada [x]
- O sistema deve permitir o cadastro de nichos e cidades para busca automática de prospects.
- Os resultados brutos retornados pela Places API devem ser armazenados temporariamente na tabela `google_places_cache`.
- O dashboard exibirá uma lista de empresas do cache, permitindo ao usuário filtrar, descartar ou converter empresas em Leads.
- Detalhes adicionais (Place Details) e score comercial só serão buscados via API quando o lead for ativado, otimizando os custos da API.

---

## Requisitos Não Funcionais

### RNF-01: Interface Premium [x]
- A estilização deve ser responsiva e visualmente premium utilizando CSS Vanilla.
- Elementos como painéis laterais de detalhes do lead, cards de pipeline, e barra de navegação devem usar glassmorphism (`backdrop-filter`).
- Hover e transições de tela devem ter animações fluidas para suavizar a experiência do usuário.

### RNF-02: Segurança e Escalabilidade de Dados [x]
- RLS (Row Level Security) ativado em todas as tabelas públicas do Supabase.
- Acesso à API do banco restrito a chaves autenticadas ou service role específicas no backend/edge functions.
- Preparação de chaves estrangeiras para futura migração multi-tenant (coluna `organization_id`).

---

## Regras de Negócio (Business Rules)
- **RN-01 (Preços)**: O agente de atendimento nunca deve enviar cotação de preços definitiva de forma automática. Qualquer menção a preço ou solicitação comercial crítica deve gerar um handoff para o corretor humano.
- **RN-02 (Opt-out)**: Se um lead solicitar remoção ou se recusar a continuar a conversa, o sistema deve registrar opt-out imediatamente e proibir qualquer nova mensagem outbound para aquele contato.
